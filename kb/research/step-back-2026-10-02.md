# Step back, 2 October 2026

Owner request: the project has many open iterations, each finished one spawns new
ones, a recent refactor did not help, and each iteration now costs well over an
hour. Re-examine the tool's purpose, the daemon, the open plans, the test/process
cost, and propose what to change. This note replaces per-iteration forensics with
one set of decisions. Supersedes the "remaining queue" in
[[rdp-takeover-2026-09-29]].

### The mechanism that generates the backlog

1. **The gating live sweep is the defect generator.** ~350 real-Firefox tests,
   including third-party sites (BBC, Guardian, HN), six workers on one laptop,
   load average 100–350. Something is red almost every run. Iteration 286's
   closing sweep alone spawned plans 289–292.
2. **Process rules make a flake impossible to close.** "Every red gets an owner
   plan", "an isolated pass is not evidence", "attribute the historical
   occurrence", "no retry, no timeout widening". A single unrepeatable event
   cannot be re-observed, so these plans end as `done` with 0/N criteria ticked
   (271, 275, 276, 277, 281, 203) or are carried forward forever (268, 289–294).
3. **The daemon design creates the real race classes** behind 259, 262, 266,
   268, 289, 292: one shared Firefox connection with no request correlation, a
   target cache that must mirror Firefox's target lifecycle across process
   switches, and a daemon-vs-direct route matrix that needs parity tests.
4. **Tests run against the developer's real Firefox and real profile root**, so
   every cleanup needs PID-birth/ownership forensics (280, 282, 203 §14).
5. **The driver's own overhead.** The Codex "root" supervisor (documented in
   `AGENTS.md`) wrapped every cargo call in censuses, receipts, SHA pins and a
   fresh independent review — a three-reference variable rename got its own
   review and its own 101 s test run.

## 2. What the tool is

ff-rdp is an **LLM agent's eyes on a page**: navigate, then inspect — text, DOM,
computed styles and cascade, console, network, screenshot, a11y, perf, eval.
`kb/analysis-2026-08-13-what-ff-rdp-became.md` reached the same conclusion. It is
not a browser-automation driver. The automation layer (`click`/`type`
act-and-see, `e<N>` refs, `run`/`record` playbooks, `index` crawl, `scroll`
sub-commands, `consent accept`) is where the daemon coupling and most third-party
-site flakiness live.

Scope rule going forward: a command earns its place if an agent debugging a
page needs it. Minimal interaction (`click`, `type`, `scroll`) stays because
reaching a state to debug needs it. Playbooks, recording, site crawling and
refs are candidates for removal or freezing.

## 3. The daemon: retire it

### Why it exists (decision-log trail)

DEC-002 (day 1) chose a stateless CLI: Firefox holds all state; ~5 ms connect
cost; "can add `--follow` later". DEC-016, the same day, reversed it, citing
50–100 ms connect overhead and connection-scoped watchers. Iteration 40 (three
days later) already concluded: "for one-shot commands (most commands) the daemon
adds complexity without benefit — it's just a TCP proxy that can interfere."
`kb/research/ff-rdp-daemon-review.md` (May) rated its key purpose — cross-call
event capture — "partially" delivered.

### What still needs it on `main`

`--ref` / `e<N>` handles, `network --since`, `throttle status` and persistent
throttle/emulate, `inspect` of grips across calls, and buffered history from
*before* the current command. Console history does **not**: `console` already
reads Firefox's own `getCachedMessages`. Streaming does **not**: `network
--follow` and `console --follow` already have `run_follow_direct`.

### Experiment, 2026-10-02 (this session, Firefox 156, debug build)

Direct connection A: `ff-rdp network --follow --no-daemon --port 6177 > net.ndjson &`.
Direct connections B, C: `navigate https://example.com/`, then
`eval 'fetch("/?probe=1")'`. Connection A received all seven events — navigation,
document GET, script GET, XHR GET, each with status and content-type — triggered
by the other connections. A one-shot `network --no-daemon` afterwards saw
nothing (expected; `--source performance-api` gave a partial fallback).

So the "agent long-polls stdout" model works today: start a follow stream, do
the work, read the file. Combined with `navigate --with-network` and
`click --wait-for-network`, nothing in the debugging use case needs a
persistent proxy process.

### Decision

1. Delete the daemon outright in one PR — no `--daemon` opt-in, no deprecation
   release (owner, 2026-10-02: "Just kill it. We don't need to be backward
   compatible."). Remove `daemon/`, registry, spawn/write locks, launch
   records, `daemon status/stop`, `_daemon`, auto-start, the `--no-daemon`
   flag itself, `meta.route`, and the daemon-vs-direct parity tests. Expected
   removal: 25–35k lines, 23 live-test files (≈7k lines), and the whole class
   of plans 259/262/266/268/289/292.
2. Rewrite the `network` hint and skill doc to teach the three capture modes:
   `navigate --with-network`, `--follow` to a file, `--source performance-api`.
3. Navigation and interaction are unaffected — verified 2026-10-02 on direct
   connections only: `launch` → `network --follow > net.ndjson &` → `navigate
   example.com` → `click 'a[href]' --wait-for-network iana` (caught the 301) →
   `page-text` / `tabs` on the new page → `console` → `screenshot`; the stream
   held 25 events across both documents (document, CSS, JS, fonts, images, with
   statuses). The page lives in Firefox; the daemon only ever held a socket and
   a buffer.
4. Refs: either drop `--ref` or store refs in the page (`eval` sets a
   `data-ffrdp-ref` attribute) so they survive across connections with no
   process. Decide after measuring how often agents use `--ref`.
5. Throttle/emulate become one-shot flags on `navigate`/`reload`, or are dropped.
6. Write the missing BiDi DEC (requested in `deep-review-2026-07-fable5.md`,
   never written): stay on RDP for its devtools actors (cascade, a11y, styles,
   sources), do not build a second transport. Revisit only if Mozilla removes
   `--start-debugger-server`.

## 5. Tests and process: the 20-minute iteration

### Tests

- **Live sweep is no longer a per-PR gate.** It runs nightly on `main` (the
  weekly `live.yml` becomes nightly, default `--jobs`), and on demand. A red
  nightly files *one* GitHub issue, not a plan.
- `launch_timeout`, `nav_dns_fail`, auth EOF under load: **retry once, then
  quarantine** (`#[ignore = "flaky: issue #N"]`). Delete the "no retry, no
  timeout widening" rule.
- **Remove wall-clock-vs-reported timing assertions** (the 750 ms gap behind
  246/264/279/291, the 2000 ms bound behind 293). They measure the laptop, not
  the product.
- **Third-party-site tests (BBC, Guardian, HN) move to a weekly `sites` canary**
  and are never gating. `consent accept` keeps its unit/fixture tests.
- Per-PR locally: `cargo test --workspace -q` (≈1–2 min) plus a *targeted* live
  run for touched modules (`cargo test -p ff-rdp-cli --test live <module> --
  --include-ignored`, 1–3 min).
- Delete the 16 iteration-numbered `FF_RDP_<N>_*` hooks, the
  `tests/iter_*_harness_*.rs` honesty tests, `lifecycle_controls.rs`,
  `startup_controls.rs` and `check_pre_fix_repro.rs` once the daemon is gone.
- Reduce `FF_RDP_*` from 51 to the ~10 user-facing ones plus `LIVE_TESTS`,
  `LIVE_NETWORK_TESTS`, `BIN`.

### Process

- **Retire the Codex root driver.** Reset `AGENTS.md` to a short pointer to
  `CLAUDE.md`; the usage-budget closeups, locks, censuses, receipts and handoff
  logs go. Keep `kb/research/rdp-*` as history only.
- `new-ralph-loop`: **one** fmt/clippy/test run after the last code change
  (skip in `/create-pr` and `/review-pr` when the tree hash is unchanged);
  **one** xtask `check-*` pass; plan ticks and `status: done` in the same
  commit as the code so there is **one** CI run; `gh pr merge --auto`.
- One reviewer pass; no re-review for style-only fixes.
- Drop from `iteration-close`: the live sweep (now nightly) and the carry-over
  sweep as a hard gate (make it a line in the PR body). Drop the coherence pass
  as a per-iteration step.
- Plan template: delete the "attributable failing occurrence", "independent
  review", "own dual-gate closing sweep" boilerplate. ACs describe
  user-visible behaviour only.
- Path filter in `ci.yml`: `kb/`-only pushes skip the Rust matrix.

Target: ≈15–20 min wall per iteration, CI (~6 min, Windows is the floor)
overlapping the review.

## 6. Low-hanging refactors (after the daemon removal)

1. `navigate.rs` (7.6k) is a readiness engine; split readiness sampling,
   consent, and network capture into modules and delete the commit-ambiguity
   guards that only existed to explain sweep reds.
2. `ff-rdp-core`: `actors/` (12k) and `fronts/` (3.2k) model the same actors;
   collapse to one layer.
3. `launch.rs` + `launch/` + `profile_dir.rs` (8k): remove managed-profile
   pruning/ownership markers once tests stop sharing the real profile root
   (every test run uses `FF_RDP_HOME=<tmp>`), keep temp-profile launch only.
4. `english_language_pack.rs` + `language_initialization*` (2k): keep only if
   147's symptom still reproduces without it; otherwise prefs-only.
5. `args.rs` help drift: the Performance-API fallback note (~line 747) is stale;
   regenerate help from behaviour and let `check-help-idioms` go.
6. Deprecated aliases (`--source auto`, `--wait-timeout`, `--vars-file`): remove.
7. 15 `allow(dead_code)` sites: resolve.
